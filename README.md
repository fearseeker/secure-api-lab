## Опис проєкту

Secure API Lab — навчальний REST API, розроблений на платформі
Node.js з використанням фреймворку Express. Проєкт демонструє
основні принципи створення серверних застосунків, маршрутизації,
аутентифікації, авторизації, валідації даних та логування
HTTP-запитів.

API забезпечує отримання, створення та видалення документів,
а також отримання конфіденційної інформації про співробітників.
Доступ до ресурсів обмежується відповідно до ролі користувача.
Усі дані зберігаються в оперативній пам'яті сервера.

## Аутентифікація та авторизація

Для доступу до захищених ресурсів необхідно передавати
HTTP-заголовки X-Login та X-Password.

У системі реалізовано дві ролі користувачів:

| Логін | Пароль | Роль |
|---|---|---|
| user1 | password123 | user |
| admin1 | password123 | admin |

Звичайний користувач має доступ до документів.
Адміністратор має доступ до документів та інформації
про співробітників.

Облікові дані є демонстраційними та використовуються
виключно для навчального проєкту.

## API ендпоінти

| HTTP-метод та URL | Опис | Заголовки | Тіло запиту | Коди відповіді |
|---|---|---|---|---|
| GET /documents | Отримання списку документів | X-Login, X-Password | Не потрібне | 200, 401 |
| POST /documents | Створення нового документа | X-Login, X-Password, Content-Type: application/json | `{"title":"Test Doc","content":"Test content"}` | 201, 400, 401 |
| DELETE /documents/:id | Видалення документа за ID | X-Login, X-Password | Не потрібне | 204, 401, 404 |
| GET /employees | Отримання списку співробітників | X-Login, X-Password (роль admin) | Не потрібне | 200, 401, 403 |

## HTTP-статуси

| Код | Назва | Опис |
|---|---|---|
| 200 | OK | Запит успішно виконано |
| 201 | Created | Новий документ успішно створено |
| 204 | No Content | Документ успішно видалено |
| 400 | Bad Request | Некоректні або відсутні вхідні дані |
| 401 | Unauthorized | Відсутні або неправильні облікові дані |
| 403 | Forbidden | Недостатньо прав доступу |
| 404 | Not Found | Документ не знайдено |

## Middleware

У проєкті реалізовано три власні middleware:

### loggingMiddleware

Фіксує інформацію про HTTP-запити в консолі сервера:
дату, час, HTTP-метод та URL запиту.

### authMiddleware

Перевіряє логін та пароль користувача, передані через
HTTP-заголовки. Якщо облікові дані неправильні або відсутні,
сервер повертає статус 401 Unauthorized.

### adminOnlyMiddleware

Перевіряє наявність ролі admin у користувача.
Якщо користувач не має необхідних прав доступу,
сервер повертає статус 403 Forbidden.

Також використовується вбудований middleware express.json()
для обробки JSON-тіла HTTP-запитів.

## Приклад створення документа

Метод: POST

URL: http://localhost:3000/documents

Заголовки:

```text
X-Login: user1
X-Password: password123
Content-Type: application/json
```

Тіло запиту:

```json
{
  "title": "Q3 Financial Report",
  "content": "The financial results for Q3 are positive."
}
```

Приклад відповіді сервера зі статусом 201 Created:

```json
{
  "id": 1795602066240,
  "title": "Q3 Financial Report",
  "content": "The financial results for Q3 are positive."
}
```

Значення ID генерується автоматично та залежить від часу
створення документа.

## Тестування за допомогою Postman

### 1. Отримання списку документів — 200 OK

Аутентифікований користувач успішно отримує список документів.

![GET 200](docs/01-get-200.png)

### 2. Створення документа — 201 Created

Сервер створює новий документ на основі отриманих даних.

![POST 201](docs/02-post-201.png)

### 3. Видалення документа — 204 No Content

Документ успішно видаляється за його ідентифікатором.

![DELETE 204](docs/03-delete-204.png)

### 4. Некоректні вхідні дані — 400 Bad Request

Сервер відхиляє запит за відсутності обов'язкових полів.

![POST 400](docs/04-post-400.png)

### 5. Відсутність аутентифікації — 401 Unauthorized

Сервер відхиляє запит без необхідних облікових даних.

![GET 401](docs/05-get-401.png)

### 6. Недостатньо прав доступу — 403 Forbidden

Звичайний користувач не може отримати список співробітників.

![GET 403](docs/06-get-403.png)

### 7. Документ не знайдено — 404 Not Found

Сервер повертає помилку при спробі видалення документа,
якого не існує.

![DELETE 404](docs/07-delete-404.png)

### 8. Доступ адміністратора — 200 OK

Адміністратор успішно отримує список співробітників.

![Admin 200](docs/08-admin-200.png)

## Логування запитів

Кожен HTTP-запит фіксується в консолі сервера.
Записи містять час отримання запиту, HTTP-метод та URL.

Логування виконується також для запитів, яким було
відмовлено в доступі.

![Logging](docs/09-logging.png)

## Тестування за допомогою Node.js

Для програмного тестування API використовується файл
test-client.js, який надсилає HTTP-запити за допомогою fetch().

Для запуску тестування необхідно запустити сервер:

```bash
npm start
```

Після цього в окремому терміналі виконати:

```bash
npm test
```

Тестовий скрипт перевіряє наступні сценарії:

| Тест | Сценарій | Очікуваний статус | Отриманий статус |
|---|---|---|---|
| 1 | Отримання документів користувачем | 200 | 200 |
| 2 | Спроба отримання співробітників користувачем | 403 | 403 |
| 3 | Отримання співробітників адміністратором | 200 | 200 |

## Обмеження проєкту

Дані зберігаються в оперативній пам'яті, тому після
перезапуску сервера всі зміни скидаються до початкового
стану, визначеного у файлі data.js.

Механізм аутентифікації реалізовано в навчальних цілях.
У реальних застосунках необхідно використовувати HTTPS,
безпечне хешування паролів та надійні механізми
керування аутентифікацією.

## Висновок

У ході лабораторної роботи було розроблено REST API
на платформі Node.js з використанням Express.

Реалізовано механізми маршрутизації, аутентифікації,
авторизації за ролями, логування HTTP-запитів,
валідації вхідних даних, створення та видалення документів.

Для перевірки роботи API використано Postman
та тестовий Node.js скрипт. Отримані результати
програмного тестування відповідають очікуваним.
